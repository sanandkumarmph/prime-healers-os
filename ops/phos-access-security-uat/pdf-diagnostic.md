# UAT synthetic PDF/runtime diagnostic

`phos_uat_pdf_diagnostic.py` is a separate diagnostic, not an installer. It validates the fixed existing PHOS UAT identity, owner, private target configuration, standard cache/storage locations and trusted runtime paths. It loads configuration without application providers or database connections. It reads no business records or mail settings, sends no email and does not activate application files.

The root supervisor requires a trusted `unshare` and establishes a different, empty network namespace. It then drops to the website owner before running PHP, Node, Composer version discovery or Chrome. If strict network isolation is unavailable, it reports refusal and does not fall back to host networking. It never changes firewall rules, services or global settings.

Only a new owner-private random `/tmp/phos-uat-pdf-probe-*` directory is used for the profile, HOME, TMP/XDG directories, an inert Puppeteer configuration and fixed synthetic PDF. Configured/shared PDF working directories are not reused. The browser uses CDP pipes and a dedicated process group. Synthetic HTML has JavaScript disabled; only fixed internal Chrome status pages can run their trusted internal scripts. All external page requests are blocked, and the network namespace also prevents background network access.

The first render removes sandbox-disabling and incompatible arguments. Actual Chrome namespace/seccomp status and command-line flags are inspected where supported. A launch alone is not reported as verified sandboxing. A separately labelled current-configuration control may run if the sandbox render fails and the current configuration already disables sandboxing. Neither result changes any setting. `engine=auto`/DOMPDF fallback is not used to mask a browser failure.

Output contains validated paths/versions, flags, safe phases/error classes and synthetic PDF size/page counts. Raw browser errors, credentials, full configuration, tokens and PDF contents are not printed. Time/output/tree sizes are bounded. Only the helper's own process group is terminated, and only its exact verified private temporary directory is removed. Cleanup drift is reported for review. Selected application/environment/cache/source fingerprints must remain unchanged.

Run only the separately supplied short bootstrap after its exact Git commit and SHA256 have been verified. The bootstrap downloads the fixed helper over verified HTTPS, checks its bytes before execution and uses a temporary root-owned0600 helper. No credentials belong in the command. A result marked `complete` establishes only this diagnostic; it does not certify deployment readiness or protection against every attack.

Offline tests run through the existing CI Python discovery step. They cover target/refusal guards, privilege/network isolation, path validation, safe output, argument filtering, cleanup and the asynchronous Puppeteer API. A separate local integration check exercised the exact Node driver against Puppeteer25/Chrome-for-Testing156 and produced a one-page synthetic PDF with no external page requests. Actual Linux/UAT namespace and sandbox support still requires the operator result.
